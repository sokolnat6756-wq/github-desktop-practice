ПЕРЕД НАЧАЛОМ

Три инструмента — одна задача

Cursor

GitHub Desktop

Просматриваем изменения, делаем Commit и Push.

GitHub.com

Храним отправленные версии проекта.

  1. Подготовьте компьютер с Windows или macOS, установленным Cursor и интернетом.
  2. Проверьте, что входите в свой GitHub-аккаунт и видите репозиторий website-vibecoder с файлами сайта.
  3. Сохраните все изменения старого проекта. Резервную копию оставьте отдельно.
Если в старой папке есть новые изменения, ещё не загруженные в GitHub, не удаляйте её. После клонирования переносите только проверенные нужные файлы, сохраняя папку .git клона. Если версии заметно отличаются, сначала попросите куратора помочь сравнить их.
Реплика спикера

Мы не будем создавать ещё один репозиторий. Подключим тот, который уже сохранили на предыдущем уроке. Клонирование создаст его рабочую копию на компьютере.

ШАГ 01

Открываем официальный сайт

  1. Откройте Страницу скачивания GitHub Desktop ↗.
  2. Для Windows выберите Download for Windows (64bit).
  3. Для Mac выберите свою архитектуру: Apple silicon для чипов Apple M-серии или Intel chip для Intel. Тип чипа указан в меню Apple → «Об этом Mac».
Основные экраны этого гайда показаны для Windows. На Mac последовательность та же; отдельные названия меню указаны рядом. Если страница не открывается, проверьте интернет и привычное стабильное подключение/VPN. Устанавливайте обычную версию, не Beta.
Реплика спикера

Программа скачивается с официального сайта. Выбираем установщик для своего компьютера, а не по внешнему виду кнопки.

ШАГ 02

Устанавливаем программу

  1. В Windows откройте «Загрузки» и дважды нажмите на скачанный GitHubDesktopSetup.exe.
  2. Дождитесь завершения установки: GitHub Desktop откроется. Если появится системное подтверждение, проверьте название программы перед разрешением запуска.
  3. На Mac распакуйте скачанный архив, перенесите GitHub Desktop в Applications / «Программы» и откройте приложение.
GitHub Desktop устанавливается на компьютер, не на телефон. Отдельная установка Git для этого маршрута не требуется. Linux официально не поддерживается этой программой.
Реплика спикера

Открываем скачанный установщик. После завершения запускаем GitHub Desktop. Здесь пока не нужны терминал и команды Git.

ШАГ 03

Входим в свой GitHub

  1. На стартовом экране нажмите Sign in to GitHub.com — «Войти в GitHub.com».
  2. Не выбирайте GitHub Enterprise: это другой вариант для организаций.
  3. Если стартовый экран уже пропущен: Windows → File → Options → Accounts; Mac → GitHub Desktop → Settings → Accounts. Выберите вход в GitHub.com.
Реплика спикера

Используем тот же аккаунт, в котором уже находится наш сайт. Создавать новый аккаунт не нужно.

ШАГ 04

Продолжаем вход в браузере

  1. Если появилось окно Sign in using your browser, нажмите Continue with browser.
  2. В браузере войдите в свой аккаунт GitHub, если вход ещё не выполнен.
  3. При запросе двухфакторной проверки введите свой текущий код в GitHub. Никому не отправляйте код или коды восстановления.
Реплика спикера

GitHub Desktop направляет нас в браузер для входа. Пароль вводим на странице GitHub, а не в чат Cursor.

ШАГ 05

Разрешаем подключение

  1. Проверьте логин аккаунта в открывшемся браузере. Это должен быть ваш аккаунт с репозиторием сайта.
  2. Если GitHub просит разрешение, нажмите Authorize desktop — «Разрешить доступ программе».
  3. Если разрешение уже выдавалось раньше, этот экран может быть пропущен.
В иллюстрациях «ваш-логин» — обозначение вашего GitHub-логина, не текст для ввода. @kopaso_va — подпись автора курса.
Реплика спикера

Мы разрешаем официальной программе работать с нашим аккаунтом. Сначала проверяем, что в браузере открыт именно нужный аккаунт.

ШАГ 06

Возвращаемся в Desktop

  1. Если браузер спрашивает «Открыть GitHub Desktop?», подтвердите открытие приложения.
  2. Вернитесь в GitHub Desktop и дождитесь завершения входа.
  3. Если программа не открылась, повторите вход через Accounts и разрешите браузеру открыть приложение. Не копируйте служебную ссылку авторизации в чат.
Реплика спикера

После подтверждения браузер вернёт нас в Desktop. Это завершает связь программы с аккаунтом.

ШАГ 07

Настраиваем подпись автора

  1. На экране Configure Git проверьте имя автора и почту, затем нажмите Finish / Continue.
  2. Если экрана нет: Windows → File → Options → Git; Mac → GitHub Desktop → Settings → Git. После изменений нажмите Save.
  3. Имя может быть вашим именем. Почта должна быть связана с вашим GitHub-аккаунтом. Для приватности используйте адрес noreply, предоставленный GitHub: Настройки почты ↗.
Имя автора коммитов не обязано совпадать с логином. Адрес noreply копируйте из своего аккаунта — не придумывайте его и не используйте учебный пример.
Реплика спикера

Git сохраняет не только изменения, но и автора. Проверяем имя и почту. Если не хотим раскрывать личную почту в коммитах, выбираем адрес noreply из настроек GitHub.

ШАГ 08

Клонируем готовый репозиторий

  1. В GitHub Desktop нажмите File → Clone repository…. На стартовом экране также может быть кнопка Clone a repository from the Internet….
  2. Выберите вкладку GitHub.com.
  3. Найдите свой website-vibecoder. Если его нет, проверьте аккаунт или используйте вкладку URL и адрес своего репозитория.
Clone — «клон», создать локальную рабочую копию вместе с историей. Add local repository предназначено для папки, где уже настроен Git; простая папка сайта после браузерной загрузки не становится Git-репозиторием автоматически.
Реплика спикера

Репозиторий уже существует на GitHub, поэтому выбираем Clone. Не New repository и не Publish repository: новый проект нам сейчас не нужен.

ШАГ 09

Выбираем именно свой сайт

  1. Выделите строку ваш-логин / website-vibecoder.
  2. Сверьте владельца и название со страницей GitHub.
  3. Если выбираете URL: вставьте ссылку на репозиторий вида https://github.com/ВАШ-ЛОГИН/website-vibecoder, а не адрес опубликованного сайта github.io.
Реплика спикера

Проверяем и название, и владельца. Так мы не начнём работать с чужим или другим проектом.

ШАГ 10

Выбираем рабочую папку

  1. В поле Local Path проверьте полный путь будущей рабочей копии. Кнопка Choose… позволяет изменить расположение.
  2. Используйте новую пустую папку назначения, например Documents/GitHub/website-vibecoder. Старую непустую папку проекта не выбирайте.
  3. Нажмите Clone и дождитесь завершения.
Клонирование не стирает прежнюю папку. После этого работаем с клоном из Local Path. Не удаляйте старый проект, пока не убедились, что в рабочей копии есть всё необходимое.
Реплика спикера

Самый важный момент — запомнить новую рабочую папку. Именно её дальше откроем в Cursor. Это не папка backup и не upload.

ШАГ 11

Открываем новую рабочую копию

  1. Вверху Desktop проверьте Current Repository: website-vibecoder. В нашем учебном репозитории ветка — main; не переключайте другую ветку наугад.
  2. Нажмите Show in Explorer — «Показать в Проводнике». На Mac — Show in Finder.
  3. Проверьте index.html, стили, скрипты, README.md и папку images. Состав зависит от вашего сайта. Клонирование также создаёт служебную папку .git; не удаляйте её.
Реплика спикера

Desktop показывает текущий репозиторий. Открываем его папку и сверяем файлы. Здесь уже хранится история Git.

ШАГ 12

Открываем эту папку в Cursor

  1. В Cursor выберите File → Open Folder… — «Файл → Открыть папку».
  2. Укажите именно папку из Local Path, которую открыл GitHub Desktop.
  3. Проверьте файлы и запустите сайт своим обычным способом. Если запуск требует сервера, используйте инструкцию проекта — не заменяйте её двойным щелчком по index.html.
Промпт для Cursor
Проверь текущую папку website-vibecoder без изменения файлов.
Укажи полный путь к ней и способ локального запуска именно этого проекта.
Проверь ссылки на стили, скрипты, изображения и другие локальные ресурсы.
Не выводи пароли, ключи или токены. Не выполняй команды Git и ничего не публикуй.
Дай короткий список того, что мне проверить в браузере.
Cursor и Desktop должны смотреть на одну и ту же папку. Авторизация GitHub в Cursor для этого маршрута не требуется: редактируем в Cursor, Commit и Push выполняем в Desktop.
Реплика спикера

Если открыть старую папку, Desktop не увидит наши новые изменения. Сверяем путь, а не только название папки.

ПО ЖЕЛАНИЮ

Cursor как внешний редактор

  1. Windows: File → Options → Integrations. Mac: GitHub Desktop → Settings → Integrations.
  2. В списке External Editor выберите Cursor, если он доступен, и сохраните настройку.
  3. Теперь можно открывать проект через Repository → Open in Cursor. Если Cursor нет в списке, используйте ручное Open Folder из предыдущего шага — этого достаточно.
Реплика спикера

Это удобный ярлык, а не обязательная интеграция. Главное — одна рабочая папка. Если Cursor не появился в списке редакторов, продолжаем через Open Folder.

ШАГ 13

Делаем безопасное изменение

Для первой проверки обновим только описание проекта, не меняя сайт.

Промпт для Cursor
Работай только с README.md текущего проекта website-vibecoder.
Сначала покажи полный путь к открытой папке, чтобы я проверила, что это клонированный репозиторий.
Сохрани существующее полезное описание.
Добавь раздел «Работа с проектом» со следующим текстом:
«Проект редактируется в Cursor. Изменения проверяются и сохраняются через GitHub Desktop».
Если этот раздел уже есть, обнови его без дублирования.
Не меняй другие файлы, дизайн и функциональность сайта.
Не добавляй пароли, токены или ключи. Не выполняй команды Git, commit, push или публикацию.
В конце покажи, что изменилось в README.md.
  1. Вставьте промпт в чат Cursor открытого клона.
  2. Сверьте путь и прочитайте изменения README.
  3. Сохраните файлы: File → Save All.
Если нужный раздел уже был добавлен и изменений нет, уточните одну реальную фразу в README. Не создавайте фиктивные изменения ради коммита.
Реплика спикера

Для первого опыта выбираем понятное изменение в README. Просим Cursor не выполнять Git-команды, потому что фиксацию и отправку сейчас учимся делать сами.

ШАГ 14

Проверяем список изменений

  1. Вернитесь в Desktop → Changes. Должен появиться изменённый README.md.
  2. Нажмите файл и прочитайте разницу: зелёные строки добавлены, красные удалены.
  3. Если появились неожиданные файлы, пароли или ключи, остановитесь и разберитесь до коммита. Не отправляйте секретные значения куратору.
Если Changes пуст: проверьте Save All, путь папки и Current Repository. Не нажимайте Discard changes: эта команда отменяет несохранённые в коммите правки.
Реплика спикера

Мы не фиксируем результат вслепую. Сначала проверяем, какие файлы изменены и что именно в них добавилось.

ШАГ 15

Сохраняем версию — Commit

  1. Оставьте галочку у проверенного README.md.
  2. В Summary (required) впишите короткое описание изменения.
  3. Нажмите Commit to main — «Сохранить версию в ветке main». Если ваша ветка названа иначе, на кнопке будет её имя.
Сообщение для поля Summary
Обновлено описание работы с проектом
Commit — «комми́т». Версия пока сохранена на компьютере. На GitHub она ещё не отправлена.
Реплика спикера

Название коммита должно объяснять изменение. Сейчас мы сохраняем версию локально. Следующее действие отправит её на GitHub.

ШАГ 16

Отправляем версию — Push

  1. Нажмите Push origin в верхней панели Desktop.
  2. Дождитесь завершения отправки. Если программа предлагает Fetch или Pull, прочитайте сообщение: на GitHub могут быть более новые изменения.
  3. При конфликте остановитесь и обратитесь к куратору. Не используйте Force push или Discard changes для его обхода.
Push origin — «пуш о́риджин», отправка сохранённых коммитов в связанный репозиторий. No local changes само по себе не доказывает, что Push выполнен: после Commit эта надпись тоже появляется.
Реплика спикера

Отправляем коммит. Теперь он должен появиться в репозитории на GitHub. Проверим это в браузере, а не только по надписи в Desktop.

ШАГ 17

Проверяем результат на GitHub

  1. В Desktop выберите Repository → View on GitHub или кнопку View on GitHub.
  2. В браузере обновите страницу репозитория. Проверьте название последнего коммита.
  3. Откройте README.md и убедитесь, что новая фраза появилась. В истории коммитов найдите созданную версию.
Если изменений нет, проверьте Push origin, владельца репозитория и ветку в браузере. Загрузка кода и публикация сайта по ссылке — разные действия; GitHub Pages настраивается отдельно.
Реплика спикера

Проверка завершена, когда мы видим новый текст в правильном репозитории и нужной ветке. Автоматической отправки всех правок Cursor нет: каждый раз выполняем Save, проверку, Commit и Push.

ГОТОВО

Ваш рабочий ритм

Открыть клон → Fetch / Pull → изменить в Cursor → Save All → проверить → Commit → Push

Перед новой работой нажимайте Fetch origin. Если доступны новые версии, нажмите Pull origin до начала правок. Если есть несохранённые изменения или конфликт, сначала разберитесь с ними.

Что отправить на проверку

Скрин GitHub Desktop с именем репозитория и скрин истории GitHub с вашим новым коммитом. Пароли, коды 2FA и токены на скринах показывать нельзя.

Короткий словарь

Clone — клон: рабочая копия с историей.
Commit — комми́т: сохранённая версия.
Push — пуш: отправка версий.
Fetch — фетч: проверка обновлений сервера.
Pull — пул: получение новых изменений в рабочую ветку.
History — хи́стори: история коммитов.

Если что-то не получилось

Репозиторий не виден: проверьте аккаунт, права и название; попробуйте вкладку URL.
Папка не пустая: выберите новый путь, не стирайте прежние файлы.
Изменений нет: проверьте открытый путь и Save All.
Push не проходит: проверьте подключение и вход; прочитайте текст ошибки. Передавайте куратору скрин без секретов.
Есть конфликты: сохраните свои файлы отдельно и попросите помочь — не отменяйте изменения наугад.
